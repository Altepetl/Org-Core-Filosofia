# Plan: Sitio estático de Org-Web (Astro + i18n)

## Objetivo
Construir el sitio estático inicial de Org-Web: una página que publica el Altepetl y recibe donaciones. Bilingüe (español primario, inglés secundario), en Astro, listo para desplegar en Cloudflare Pages con dominio `altepetl.kinam.org`.

## Decisiones ya acordadas
- **Naturaleza:** sitio estático (no app).
- **Generador:** Astro (requiere Node 22.12+).
- **Hosting:** Cloudflare Pages.
- **Dominio:** `altepetl.kinam.org`.
- **Idiomas:** español neutro (primario) + inglés, en `/es/` y `/en/`.
- **Donaciones:** Stripe + MercadoPago (ambos, como opciones en la página de donación).

## Alcance del sitio inicial (MVP)

4 páginas por idioma (8 total):

1. **Inicio (`/`)** — Presentación del Altepetl: qué es, misión, valores principales, llamado a participar/donar.
2. **Filosofía (`/filosofia`)** — Resumen legible de los puntos clave de la Filosofía (no el documento completo, sino una versión comunicativa). Link al documento completo en GitHub.
3. **Participa (`/participa`)** — Cómo involucrarse: crear o unirse a un Calpulli, contacto inicial.
4. **Donaciones (`/donaciones`)** — Botones/links de Stripe y MercadoPago, transparencia sobre uso de recursos.

Más:
- **Redirección raíz** (`/` → `/es/` por defecto, con detección de `Accept-Language` para sugerir `/en/` si aplica).
- **404** localizada.

## Decisiones de diseño visual

- **Sin framework CSS.** CSS puro con custom properties (variables) para mantener todo simple y rápido. Es un sitio estático pequeño.
- **Tipografía system-ui.** Sin fuentes externas por defecto (privacidad + velocidad). Una fuente display se puede considerar más adelante, pero no para el MVP.
- **Paleta sobria.** Tonos tierra/verde olivo (conexión con la tierra, el Cem Anahuac, los valores de vida y entorno). Sin colores saturados ni estética de red social comercial.
- **Accesibilidad WCAG 2.1 AA.** Contraste, navegación por teclado, texto alt, HTML semántico.
- **Responsive mobile-first.** Diseñado primero para móvil, escala a escritorio.
- **Sin JavaScript en cliente.** El selector de idioma usa enlaces (`<a>`), no JS. Astro permite interactividad cero si no hay componentes `client:*`.

## Contenido de cada página

### Inicio
- Hero: nombre "Altepetl", tagline corto, CTA "Conoce la Filosofía" + "Donar".
- Sección "Qué es" (1 párrafo).
- Sección "Misión" (1 párrafo).
- Sección "Valores" (lista: La vida, El hombre, El amor, La Bondad).
- Sección "Llamado a participar".
- Footer con links.

### Filosofía
- Versión comunicativa de los puntos clave (no el documento crudo).
- Resumen del camino hacia el Kinam.
- Resumen de los pilares (Calpulli, organizacion social, etc.).
- CTA al documento completo en GitHub.

### Participa
- Qué es un Calpulli.
- Cómo unirse o crear uno (formulario de contacto inicial o email).
- Canales de comunicación.

### Donaciones
- Por qué donar (conexión con la Filosofía).
- Botones Stripe y MercadoPago.
- Transparencia: cómo se usan los recursos (link a la sección de la Filosofía sobre captación de recursos).

## Dependencias

Solo las mínimas:
- `astro` (última estable).
- `@astrojs/cloudflare` (adapter para Cloudflare Pages, aunque para sitio 100% estático no es estrictamente necesario — Cloudflare Pages sirve el `dist/` directamente).

**Sin dependencias de UI, sin framework CSS, sin iconos npm.** Favicon SVG propio.

## Integración de donaciones (placeholder listo para claves reales)

- `DonationButtons.astro` con dos botones:
  - **Stripe:** link a Stripe Payment Link (configurable vía variable de entorno `STRIPE_PAYMENT_LINK` o directo en el componente). En el MVP, placeholder `<a href="#" data-provider="stripe">`.
  - **MercadoPago:** link a MercadoPago (similar).
- Las claves reales se configuran en producción; en el repositorio solo quedan los placeholders.

## Configuración de despliegue (Cloudflare Pages)

- Documentada en el README (build command: `npm run build`, output: `dist`).
- Sin adapter especial para sitio estático puro — Cloudflare Pages sirve el `dist/` directamente.
- Variables de entorno para los links de pago se configuran en el dashboard de Cloudflare.

## Tareas de implementación

1. Inicializar proyecto Astro (manualmente, sin el CLI para control fino de archivos).
2. Configurar `package.json`, `astro.config.mjs`, `tsconfig.json`.
3. Crear layout base y componentes (Header, Footer, Hero, DonationButtons, LanguageSwitcher).
4. Crear `global.css` con paleta y tipografía.
5. Crear archivos de contenido (`es.json`, `en.json`) con todos los textos.
6. Crear páginas ES (4) + página index con redirección a `/es/`.
7. Crear páginas EN (4) — traducción de las ES.
8. Crear 404 localizada.
9. Crear `public/favicon.svg` y `public/robots.txt`.
10. Actualizar `.gitignore` (ya está OK), README (con instrucciones de build y deploy) y CHANGELOG.
11. Build local para verificar.
12. Commit.

## Lo que NO incluye (deliberadamente)
- Sin blog, sin CMS, sin panel admin.
- Sin analytics (se decide más adelante).
- Sin formulario de contacto funcional (placeholder mailto o link a canal externo).
- Sin red social interna.
- Sin buscador.
- Sin registro de usuarios.
- Sin integración con la blockchain del Altepetl (cuando exista, se añade).
- Sin dark mode (se puede añadir después, no bloquea el MVP).

## Verificación
- `npm run build` debe generar `dist/` con las 8 páginas + index redirect.
- Las páginas ES son las primarias (`/` redirige a `/es/`).
- Cada página tiene su contraparte EN y viceversa, con selector de idioma que conmuta.
- Las páginas pasan validación básica de HTML accesible.
